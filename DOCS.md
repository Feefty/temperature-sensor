## Architecture

Hexagonal (Clean) Architecture with three layers and strict dependency rule: **Domain ← Application ← Infrastructure**. Inner layers have zero knowledge of outer ones. The domain defines **ports** (interfaces); infrastructure provides **adapters** (implementations).

### Layer Breakdown

| Layer              | Responsibility                                                     | Depends on                   |
| ------------------ | ------------------------------------------------------------------ | ---------------------------- |
| **Domain**         | Business rules, value objects, port interfaces                     | Nothing                      |
| **Application**    | Use case orchestration (read sensor → classify → persist → return) | Domain ports only            |
| **Infrastructure** | Concrete adapters: SQLite, HTTP server, sensor sim                 | Domain ports, framework code |

### API Endpoints

| Method | Path                      | Description                                         |
| ------ | ------------------------- | --------------------------------------------------- |
| GET    | `/api/sensor/temperature` | Read sensor, classify, persist, return reading      |
| GET    | `/api/sensor/history`     | Last 15 readings (most recent first)                |
| GET    | `/api/sensor/thresholds`  | Current cold/hot thresholds                         |
| PUT    | `/api/sensor/thresholds`  | Update thresholds `{ coldThreshold, hotThreshold }` |

### Data Flow (GET /api/sensor/temperature)

```
HTTP Request
  → routes.ts (Elysia handler)
    → TemperatureService.readCurrentTemperature()
      → ThresholdsRepository.get()          ← SQLite
      → TemperatureSensorPort.read()        ← RandomTemperatureSensor
      → Thresholds.determineState(temp)     ← pure domain logic
      → TemperatureRepository.save(reading) ← SQLite
    ← returns TemperatureReading
  ← HTTP 200 JSON response
```

### Persistence — SQLite (bun:sqlite)

Two tables, auto-created on first run:

```sql
temperature_readings (
  id TEXT PRIMARY KEY,
  temperature_celsius REAL NOT NULL,
  state TEXT NOT NULL,
  timestamp TEXT NOT NULL
)

thresholds (
  id INTEGER PRIMARY KEY CHECK (id = 1),  -- single-row enforcement
  cold_threshold REAL NOT NULL,
  hot_threshold REAL NOT NULL
)
```

Thresholds table is seeded with defaults (cold=22, hot=35) on first startup if empty. DB file lives at `data/sensor.db` by default, configurable via `DATABASE_PATH` env var.

## Tool Choice Justifications

### Bun (runtime)

- **TypeScript native** — no `ts-node`, no `tsc --watch`, no bundler needed. Run `.ts` files directly.
- **bun:sqlite built-in** — zero-dependency SQLite. No `better-sqlite3` or `sql.js` to install or compile.
- **Single binary** — deployment is just `bun start`, no Node.js version management.
- **Fast** — startup and script execution are significantly faster than Node, relevant for tight dev loops.

### Elysia (web framework)

- **Bun-native** — designed for Bun's API surface, no polyfills or shims.
- **End-to-end type safety** — TypeScript types flow from request validation through to response. Catches contract mismatches at compile time.
- **Lightweight** — minimal abstraction over HTTP. The whole app is ~50 lines of route definitions.

### valibot (validation)

- **Tree-shakeable** — import only the schemas you use. Bundle stays small.
- **No decorators, no reflection** — pure functions. Simpler mental model than class-validator or zod's `.parse()` chaining.
- **Composable** — `pipe(number(), minValue(-273.15))` reads as a pipeline, easy to extend.

### Husky + lint-staged (quality gate)

- **Pre-commit hook** runs Prettier formatting then `tsc --noEmit` on staged files only — catches type errors and formatting issues before they reach git.
- **Zero-config** after setup. `lint-staged` filters to staged files, keeping the hook fast.
- Prevents the "formatting commit" pattern and CI type-check failures.

## Testing

### Running tests

```bash
bun run test        # Jest (Node)
bun run test:bun    # Bun test (for Bun-specific features)
```

### Test layout (co-located `__tests__/`)

| Location                                                                         | What it covers                                                                                  |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `src/domain/__tests__/Temperature.test.ts`                                       | Validation: NaN, absolute zero, edge cases                                                      |
| `src/domain/__tests__/Thresholds.test.ts`                                        | State matrix (HOT/COLD/WARM), creation invariants, defaults                                     |
| `src/application/__tests__/TemperatureService.test.ts`                           | Orchestration with mocked ports — all 3 state paths, history slicing, threshold updates         |
| `src/infrastructure/persistence/__tests__/InMemoryTemperatureRepository.test.ts` | Save + findLast: ordering, limit, empty state                                                   |
| `src/infrastructure/persistence/__tests__/InMemoryThresholdsRepository.test.ts`  | Defaults, update persistence, idempotency                                                       |
| `src/infrastructure/sensor/__tests__/RandomTemperatureSensor.test.ts`            | Range [-10, 50], decimal precision, custom config                                               |
| `src/infrastructure/web/__tests__/routes.test.ts`                                | HTTP integration via Elysia's `app.handle()` — status codes, response shapes, validation errors |

Application-layer tests use the in-memory repositories as stubs, keeping them fast and framework-independent. HTTP tests exercise the full stack (routes → service → in-memory repos).
